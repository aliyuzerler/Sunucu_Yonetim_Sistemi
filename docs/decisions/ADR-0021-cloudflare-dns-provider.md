# ADR-0021: Cloudflare DNS Provider — Real Provider Adapter on the Faz 09 Contract

- Status: Accepted (Phase 16)
- Context: Faz 09, DNS sağlayıcı adaptör mimarisini (ADR-0013) sabitledi: Provider arayüzü kontrol panelinde yaşar, kimlik bilgileri AES-256-GCM mühürlüdür, her mutasyon ValidateRecord + diff önizleme disiplininden geçer. O fazda yalnız yerleşik `mock` sağlayıcı uygulandı — gerçek sağlayıcı entegrasyonları bilinçli olarak kapsam dışı bırakıldı ("kullanıcı istemedikçe ücretli servis entegrasyonu" kapsam koruması; test edilemezlik). Kullanıcı Faz 16'da gerçek sağlayıcı talep etti; **Cloudflare seçildi** çünkü (a) DNS yönetimi API'si ücretsizdir (kayıt firması değil, DNS barındırma), (b) API v4 basit REST + JSON'dur, (c) DNS-01 (ACME wildcard) desteği tamdır.
- Decision:
  1. **Yalnız stdlib istemci:** `internal/dns/cloudflare.go` — net/http + encoding/json ile Cloudflare API v4. Yeni harici Go bağımlılığı YOK (Faz 14 S3 adaptörüyle aynı disiplin). Yeniden deneme (retry) YOK: 4xx/5xx yanıtlar tipli `ErrAPI` ile dürüstçe döner; sessiz yeniden deneme sorunları maskeler, operatör görevi yeniden çalıştırır.
  2. **Kimlik bilgisi sözleşmesi:** `{"api_token": "..."}` — Cloudflare "API Token" (Bearer). CreateProvider anında doğrulanır (şema + boş/uzunluk sınırı; API çağrısı yapılmaz), mühürlü saklanır, yalnız Authorization başlığında taşınır; hata mesajı/log/sonuç payload'ına ASLA yazılmaz (testte sızma negatifi var). Önerilen kapsam: Zone.DNS Edit + Zone.Read (yalnız hedef bölgeler).
  3. **Arayüz değişikliği YOK:** Provider sözleşmesi (Capabilities/Zones/Records/ApplyChange) birebir korunur — mock ile aynı doğrulama katmanı, aynı diff önizleme, aynı executor yolları (dns.zone.list, dns.record.*), aynı ACME DNS-01 köprüsü (SetTXTRecord). Beklenmedik türlere tahminle izin verilmez: bilinmeyen kind hâlâ tipli red (Route53 vb. ayrı ADR gerektirir).
  4. **Dürüst kapsam sınırları:**
     - Bölge OLUŞTURMA arayüzde yok (Provider.Zones salt liste) — Cloudflare hesabında bölge açılır; alan adı satın alma zaten panel dışıdır. Panel **mevcut** bölgelerin kayıtlarını yönetir.
     - Kayıt türleri panelin KAPALI kümesiyle sınırlı (A, AAAA, CNAME, TXT, MX); Cloudflare'in NS/SOA/SRV/CAA gibi türleri listelerde filtrelenir, panel üzerinden yazılmaz.
     - Cloudflare "auto" TTL (API'de ttl=1) 60 olarak raporlanır/gönderilir; ayrım capabilities.Note ile beyan edilir.
     - Sayfalama tavanı 40 sayfa × 50 = 2000 (panel MaxZones/MaxRecords sınırıyla uyumlu).
  5. **Hermetik test:** sahte Cloudflare API v4 (httptest) — sayfalama, FQDN↔göreli ad eşlemesi (apex "@", wildcard "*.sub"), MX priority birleşimi, CNAME nokta temizliği, create/update/delete yolları, 403/success=false/şema hataları, token sızma negatifi. PG entegrasyonu: cloudflare türünün kalıcılık yuvarlama turu (testdb).
- Consequences: Kullanıcı artık gerçek Cloudflare bölgelerini panel üzerinden yönetebilir ve ACME DNS-01 ile wildcard sertifika üretebilir; "DNS yalnız mock" kısıtı kalktı. Route53/Google DNS vb. yeni sağlayıcılar aynı şablonla eklenir (BuildX + httptest sahte süit + ADR). Sahte sunucu gerçek API sürüm değişikliklerini yakalayamaz — gerçek hesapla ilk kurulumda `dns.zone.list` smoke testi önerilir.
