# ADR-0022: Hash Tabanlı URL Yönlendirme — Paylaşılabilir Görünüm Adresleri ve NodeDetail Derin Bağlantısı

- Status: Accepted (UX Denetimi P1 — m.4.1/m.4.2)
- Context: UX kullanılabilirlik denetimi (2026-11, `Server-Control-Kullanilabilirlik-Denetim-Raporu.pdf`) m.4.1'de saptadı: gezinme `App.tsx` içindeki `useState("overview")` ile yönetiliyordu — URL ile görünüm arasında hiçbir bağ yoktu. Sonuç: tarayıcı geri/ileri tuşları çalışmıyor, sayfa yenileme her zaman Genel Bakış'a atıyor, hiçbir görünüm yer imine eklenemiyor/paylaşılamıyor. m.4.2 ise NodeDetail'in `NodesPage` içinde koşullu render edilip adreslenememesiydi (bir node'un detayı için her zaman listeden gezinmek gerekiyordu).
- Decision:
  1. **Hash yönlendirme, react-router YOK:** `web/src/navigation/router.ts` — iki saf fonksiyon (`parseHash`, `buildHash`) ve `App.tsx`'te `hashchange` dinleyicisi. Biçim: `#/<sayfa>` ve `#/nodes/<node-id>`. Boş/bilinmeyen hash → `#/overview`; bilinmeyen sayfa mevcut ComingSoon davranışını korur. Yeni harici bağımlılık YOK (proje ilkesi; SPA kabuğunun toplam bundle boyutu korunur). path-based History API yerine hash seçildi: statik dosya sunucusunda sunucu-tarafı rewrite gerektirmez (vite preview + üretim dağıtımı aynı davranır), mock API ve gerçek API proxy yapılandırmasına dokunmaz.
  2. **URL tek doğruluk kaynağıdır:** `route` state yalnız hash'ten türetilir. Uygulama içi gezinme (`navigate`) görünümü İYİMSER ve SENKRON günceller (tıklama → render aynı commit'te; hashchange bir makro-görev sonra aynı değeri tekrar bildirir — zararsız) ve hash'i yazar. Geri/ileri tuşları ve elle hash düzenlemesi yalnız `hashchange` üzerinden akar. Bu ikili yapı, eski senkron state zamanlamasını korurken URL senkronunu ekler (E2E helper'larındaki "tıkla → hemen doğrula" desenleri kırılmaz).
  3. **NodeDetail adresleme (m.4.2):** `#/nodes/<id>` → `NodesPage` seçimi prop'tan türetir (`routeNodeId`). Derin bağlantıdaki node ilk sayfada (limit=100) yoksa tekil `GET /api/v1/nodes/{id}` uç noktasından çekilir; bulunamazsa dürüstçe liste görünümünde kalınır. Satır "Detay" tıklaması `onOpenNode(id)` → hash `#/nodes/<id>`; NodeDetail "Node listesine dön" → `#/nodes`. Böylece detay görünümü de yer imi/geri tuşuyla tam desteklenir.
  4. **Erişilebilirlik eşliği (m.4.3 ile birlikte):** ConfirmDialog gerçek `role="dialog"` + `aria-modal` + Escape + odak-yönetimi taşır; ToastProvider `role="status"` + `aria-live="polite"` bölgede yaşar. `window.confirm` kaldırıldı (5 çağrı noktası: Extensions ×2, Dns ×1, Updates ×2).
  5. **Dil tercihi kalıcılığı (m.4.5):** `LocaleProvider` sırayla localStorage (`servercontrol.locale`) → `navigator.language` (tr öneki) → `"tr"` okur/yazar; `<html lang>` güncellenir. Depolama hataları (gizli mod) try/catch ile yutulur — uygulama çalışmaya devam eder.
- Consequences: Her görünüm paylaşımlı/adreslenebilir; geri/ileri/yenileme doğru çalışır. Hash değişimi History API kayıtlarıyla sınırlıdır — sunucu loglarında SPA rotaları görünmez (kabul edilebilir: kontrol paneli tek kullanıcılı self-hosted). `parseHash`/`buildHash` saf birim testlidir; App düzeyi derin bağlantı/geri tuşu testleri ve 6 senaryolu `e2e/ux-p1.spec.ts` davranışı sabitler. Dışsal maliyet: doğrudan hash yazan test/araçlar artık görünümü etkiler (bilinçli kabul — özellik budur).
