# ADR-0008: Agent Protocol, mTLS Identity and Enrollment

- Status: Accepted (Phase 03)
- Context: Phase 03 requires the protobuf/gRPC contract, the enrollment flow, mTLS identity, heartbeat and capability reporting. The agent must always dial outbound; the server never connects to nodes; the agent's private key must never leave the node; enrollment tokens must be single-use, short-lived, scoped and replay-protected; revoked certificates must be rejected.

## Decision

1. **One proto file, one wire version.** `proto/servercontrol/agent/v1/agent.proto` defines `EnrollService` (server-TLS only) and `AgentService.Connect` (mTLS bidi stream). Envelopes (`AgentEnvelope`/`ServerEnvelope`) carry `request_id`, `node_id`, `correlation_id`, `issued_at`, `expires_at`, `idempotency_key`; unknown enum values must be handled safely; field numbers are never reused. Generated code lives in `gen/proto` (own Go module, consumed via `replace`) and is regenerated with pinned `buf`/plugins (`make proto-check` gates CI).
2. **Key generation stays on the node.** The agent generates an ECDSA P-256 key locally (file 0600) and submits only a PKCS#10 CSR. The server ignores any SAN in the CSR and embeds the immutable node ID as URI SAN `urn:servercontrol:node:<uuid>` in the issued leaf (ClientAuth EKU, DigitalSignature only).
3. **One CA, two identities.** A single operator-provisioned ECDSA CA (`control-plane ca init`, key file 0600, never in the DB, never transmitted) signs both the ephemeral gRPC server certificate (localhost/hostname/IP SANs, regenerated at startup) and node client certificates. Agents pin the CA: the enroll response's `ca_pem` must byte-match the operator-provided `ca.crt` (MITM guard), and the CA file is the trust root for both enroll and stream connections.
4. **Enrollment tokens: single-use, scoped, atomic.** `enrollment_tokens` stores only the SHA-256 digest with `scope_type ∈ {node, group}`, TTL ≤ 1h, `consumed_at`, `revoked_at`. Consumption takes `FOR UPDATE` on the token row inside ONE transaction that also claims/creates the node, records `node_certificates` (fingerprint, serial, validity) and stamps agent metadata. A concurrent second use fails (RowsAffected check + row lock, proven by test). Group-scope tokens create the node in that group; node-scope tokens adopt an existing non-retired node.
5. **Stream authorization is per-connection, per-message.** `Connect` requires a client certificate (TLS `VerifyClientCertIfGiven` + handler-level enforcement): chain must verify against the CA (handshake), the fingerprint must map to an `active` `node_certificates` row of an existing non-retired node, and every envelope's `node_id` must equal the certificate identity (else PermissionDenied). Revoked/expired certificates are rejected at connect time (DB-level revocation; CRL/OCSP stapling is future work tracked in project-status).
6. **State machine on the stream.** First envelope must be `Hello` (protocol version v1 enforced; version mismatch fails loudly). Server acks with heartbeat interval. `Heartbeat` refreshes `nodes.last_seen_at`/`status=active`. `CapabilityReport` upserts `node_capabilities` (server-authoritative capability checks remain at operation time). Expired envelopes (agent→server or server→agent) are dropped, never executed.
7. **Task dispatch over the stream.** Tasks carry `execution_target` (`control_plane` | `node`). Node-targeted tasks are claimed per connected stream with `FOR UPDATE SKIP LOCKED` + a 60s lease, delivered as `OperationRequest` (task id, operation, version, JSON payload; envelope adds deadline, idempotency key, correlation). The agent validates (registry allowlist, payload schema, size, version) and answers terminal `OperationResult` (SUCCEEDED/FAILED/REJECTED); the server applies results only while the task is `dispatched` and node matches. Lost streams leave the lease to expire; retry-safe tasks requeue (Faz 02 engine unchanged otherwise).
8. **Agent execution is allowlisted and bounded.** Faz 03 ships only `agent.echo` (typed JSON echo ≤256 chars) — proof of the loop without touching the host (OS operations are Phase 04). Unknown operations are REJECTED, never executed. A bounded idempotency cache (256 entries, 30 min) replays stored results for duplicate task IDs. Reconnect uses exponential backoff with jitter (cap 30s).

## Consequences

- Certificate revocation is DB-backed and checked at connect time; long-lived streams of a revoked node persist until reconnect (bounded by heartbeat interval). CRL/OCSP and mid-stream revocation are future work.
- The CA private key compromise compromises the whole fleet; the key must stay on the control plane host with 0600 and offline backup. Rotation requires a new ADR.
- One live stream per node per process; a second simultaneous Connect is rejected (ResourceExhausted) — the agent retries with backoff. HA control planes would need a shared hub (ADR-0006 scale-out path).
- `gen/proto` as a separate module keeps backend and agent builds independent while sharing the wire contract.
