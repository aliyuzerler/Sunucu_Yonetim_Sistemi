# ADR-0018: Yedekleme/Geri Yükleme ve Bulut Sağlayıcı Bağdaştırıcıları — Ayrık Kapsamlar, Zorunlu Doğrulama, Anahtar Ayrımı, Onay Kapılı Silme

- Status: Accepted (Phase 14)
- Context: Faz 14 kabul kriterleri beş zorunluluk koyar: (1) Control Plane yedeği ile node veri yedeği ayrılmalı; (2) yedek bütünlük/doğrulama durumu raporlanmalı ve restore İZOLE hedefte denenmeli; (3) şifreleme anahtarı yedek deposuyla aynı yerde tutulmamalı; (4) en az 2-3 node ile task izolasyonu, offline node, reconnect, retry ve sertifika iptali test edilmeli; (5) bulut sağlayıcı bağdaştırıcıları her sağlayıcı için ayrı kapsam/kimlik/izin matrisi kullanmalı ve kaynak silme onay gerektirmeli. `docs/operations/backup-restore.md` restic'i node yedeği motoru olarak seçer ve "başarılı yedek komutu geri yüklenebilirlik kanıtı değildir" ilkesini koyar.

## Decision

1. **İki ayrı yedek kapsamı (kriter 1).** `backups` tablosu `scope ∈ {control_plane, node}` kapalı enum'u taşır; CHECK kısıtı `(scope='node') = (node_id IS NOT NULL)` yapısaldır: node yedeği node'suz, CP yedeği node'lu kaydedilemez. CP yedeği kendi PostgreSQL'inin COPY tabanlı mantıksal dökümüdür (tek REPEATABLE READ işlemi — veritabanı-yerel tutarlılık; canlı dosya kopyalanmaz); node yedeği node'daki restic deposudur (broker ailesi `--backup-enable`, varsayılan KAPALI). İki kapsam farklı motorlar, farklı kayıt sınıfları ve farklı RBAC izinleriyle (backup:read/backup:control) yönetilir.
2. **Doğrulama zorunluluğu + izole restore tatbikatı (kriter 2).** Her CP dökümü, yazılır yazılmaz sha256 footer + satır sayıları üzerinden yeniden doğrulanır; `verify_state ∈ {unverified, verified, failed}` kaydı "yedek başarılı" demek için gerek koşuldur (unverified asla verified gösterilmez). Node tarafında `backup.run` inline `restic check`, `backup.verify` ise `--read-data-subset=10%` gerçek veri örnekleme denetimi yapar; node raporu CP kaydına dürüstçe taşınır. Restore: CP yedeği için `restore_drills` kaydıyla YENİ yaratılan `scp_drill_xxxxxxxx` izole veritabanına gömülü migration'larla şema + COPY ile veri geri yüklenir, tablo başına satır sayıları karşılaştırılır, tatbikat sonunda veritabanı düşürülür; node yedeği için hedef yalnız yönetilen izole restore kökü (`/var/backups/server-control/restore/rest-<rand>`) altındaki YENİ dizin olabilir — payload'da hedef alanı YOKTUR. Canlı veriye restore bu fazda YOKTUR (dürüst kapsam).
3. **Anahtar ayrımı (kriter 3).** CP_SECRETS_KEY yalnız ortamdan gelir; hiçbir kod yolu onu yedek dizinine yazmaz. Ek olarak iki katmanlı savunma: (a) operatör bir anahtar dosyası kullanırsa `ValidateKeySeparation` symlink-çözümlemeli içerme denetimiyle repo içindeki dosyayı tipli reddeder; (b) her doğrulama pass'i artifact'i anahtar malzemesi için tarar — sızma bulursa doğrulama `ErrKeyMaterialInBackup` ile BAŞARISIZ olur (fail-closed). Node tarafında restic parolası RESTIC_PASSWORD_FILE ile (asla argv/env düz metin) taşınır, parola dosyası `/etc/server-control/backup/` kökünde (repo kökünden ayrı) tutulur ve her işleyişte yapısal ayrım yeniden denetlenir; parola hiçbir sonuç/audit/günlük yüzeyine çıkmaz.
4. **Multi-node kanıt (kriter 4).** `agentsrv` paketinde gerçek PostgreSQL + gerçek TLS üzerinde üç sanal node ile beş kaos/load testi: task izolasyonu (sıkışan node diğer node'ların dağıtımını bloklamaz; yanlış node sonucu reddedilir), offline node kuyruğu + reconnect teslimi, lease/retry sözleşmesi (retry-safe requeue; deneme tavanı `lease_expired` ile dürüst fail), 3 node × 10 görev throughput (attempts=1 disiplini) ve sertifika iptali/emeklilik sonrası `Unauthenticated` red kanıtı.
5. **Bulut sağlayıcı çerçevesi + ilk adaptör (kriter 5).** `internal/cloud` sağlayıcı arayüzü her kind için ayrı `PermissionMatrix` (action → sağlayıcı izni + risk sınıfı + confirm zorunluluğu) bildirir; matris UI'da birebir gösterilir. İlk adaptör S3-uyumlu nesne depolamadır (AWS SigV4, yalnız stdlib; path-style). Kimlik bilgileri AES-256-GCM mühürlüdür (ADR-0013 disiplini), yaz-amaçlıdır. Kaynak silme: onay kapısı SERVİS sınırlarında zorlanır (confirm olmadan `ErrConfirmationRequired` — UI atlatamaz); dolu kaynakta sağlayıcının 409'u tipli `ErrResourceNotEmpty`'e eşlenir — panel asla zorla silmez. Uç nokta https zorunludur (yalnız döngü adresi http istisnası, testler için).

## Consequences

- CP yedeği pg_dump yerine COPY tabanlıdır: harici ikili gerektirmez, CI'da her koşuda gerçek restore-tatbikatı kanıtı üretilir; karşılığında döküm CP şemasına özeldir (public şeması + gömülü migration'larla oynanır) ve pg_dump/custom-format özellikleri (sıkıştırma, paralel) bu fazda yoktur — operasyonel büyüme durumunda ayrı bir ADR ile genişletilir.
- `restic forget/prune` (depo kırpma/rotasyon) bu fazda BILINÇLI olarak kapsam dışıdır: silme yüzeyi büyütülmeden yalnız ekleme + doğrulama + izole restore sağlanır; rotasyon ihtiyacı ayrı karar konusudur.
- Backup verify/restore drill'leri CP worker'ında 5 dakikalık tipli zaman aşımıyla çalışır; büyük veritabanlarında drill süresi izlenmelidir (worker kuyruğu diğer görevleri bloklamaz — SKIP LOCKED leasing).
- S3 SigV4 stdlib ile uygulanır (~150 satır); resmi AWS SDK eklenmedi. Sağlayıcı sayısı büyürse her adaptör kendi sınama paketiyle ayrı sürümlenir (feature-matrix: "Each provider separately tested").
